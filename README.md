# KuCoin Go SDK

![KuCoin Golang API SDK](https://i.postimg.cc/3xK6Brxs/kucoin-go-github.jpg)

[![Go Version](https://img.shields.io/badge/go-%3E%3D1.22-blue)](go.mod)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

An idiomatic Go client for KuCoin's **UTA (Unified Trading Account)** and **Classic (Spot/Margin/Futures)** REST and WebSocket APIs, written from scratch against KuCoin's current `docs-new` documentation — not a wrapper around the official Universal SDK.

**Package:** a matching PHP/Laravel SDK is available at [tigusigalpa/kucoin-php](https://github.com/tigusigalpa/kucoin-php).

---

## Why this exists

KuCoin's official Universal SDK is generated code that tries to cover every language and every account model at once, and it shows: inconsistent naming, loosely typed fields, and error handling that varies by endpoint. This project takes the opposite approach — hand-written, one endpoint at a time, with a single consistent shape for requests, responses, and errors across the whole SDK. The trade-off is honest: coverage grows slower, but what's there is tested, typed, and documented against KuCoin's real docs rather than against generator templates.

If you need full API coverage today, use the official SDK. If you want a smaller, carefully built Go client and can wait for coverage to grow (or want to contribute an endpoint yourself), this is for you.

---

## Status

**This is an early, honest checkpoint, not a finished library.** Only **UTA public market data** is implemented and tested so far. Everything else described in this project's roadmap — UTA Account/Orders/Positions/Leverage/Transfers, Classic Spot/Margin/Futures trading, and every WebSocket channel — is **not yet implemented**. See [docs/ENDPOINTS.md](docs/ENDPOINTS.md) for the exact, generated list of what's covered, with a direct KuCoin documentation link per method.

| Phase | Scope | Status |
|---|---|---|
| 1 — reliable core | Shared HTTP/auth/error/retry infra; UTA market/account/orders; Classic Spot market/orders; Classic Futures market/order/position; UTA + Classic WS core channels | **Partial** — shared infra + UTA Market done; the rest is not started |
| 2 — trading breadth | Classic Margin; advanced Spot/Margin orders; UTA positions/leverage; more WS channels | Not started |
| 3 — specialty domains | Account/funding/subaccounts/deposits/withdrawals, Earn, VIP Lending, Convert, Broker, Affiliate, Copy Trading | Not started |

We'd rather ship a small, correct surface than a large, half-tested one. If your use case needs something from Phase 2 or 3, please open an issue — real demand is what decides what gets built next.

## What's inside (so far)

- `context.Context` as the first parameter of every network call
- An injectable `*http.Client`, `Clock`, and `Logger`
- Strings for every price/quantity/PnL/fee field — no float rounding errors
- Independent HMAC-SHA256 signer (`KC-API-SIGN` and the HMAC-signed `KC-API-PASSPHRASE`), verified against known-answer fixture vectors
- A shared `transport.Executor`: response envelope decoding, `ResponseMeta` (HTTP status, KuCoin business code/message, request ID, `gw-ratelimit-*`, `x-in-time`/`x-out-time`), and a typed error hierarchy (`errors.Is`/`errors.As`)
- A conservative retry policy — **GET requests only**, exponential backoff with jitter, bounded max-elapsed time; POST/DELETE (place/cancel/amend orders, transfers, withdrawals) are never auto-retried
- A manifest-driven [docs/ENDPOINTS.md](docs/ENDPOINTS.md), regenerated by `go run ./internal/gendocs` from [internal/endpoints.yaml](internal/endpoints.yaml); CI fails if they drift apart

## Quick start

Public market data works with zero credentials — a good way to try the SDK before deciding whether to trust it with real keys:

```go
package main

import (
	"context"
	"fmt"
	"log"

	kucoin "github.com/tigusigalpa/kucoin-go"
	"github.com/tigusigalpa/kucoin-go/uta/market"
)

func main() {
	client := kucoin.NewClient()

	tickers, err := client.UTA.Market.GetTickers(context.Background(), market.TradeTypeSpot, "BTC-USDT")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(tickers.List[0].LastPrice)
}
```

Runnable example: [examples/uta_market](examples/uta_market/main.go).

## Credentials and security

Read `KC-API-KEY`/`KC-API-SECRET`/`KC-API-PASSPHRASE` from environment variables or your own secret store — never hardcode them:

```go
client := kucoin.NewClient(kucoin.WithCredentials(kucoin.Credentials{
	APIKey:        os.Getenv("KUCOIN_API_KEY"),
	APISecret:     os.Getenv("KUCOIN_API_SECRET"),
	APIPassphrase: os.Getenv("KUCOIN_API_PASSPHRASE"),
	APIKeyVersion: os.Getenv("KUCOIN_API_KEY_VERSION"), // per-key metadata, not a constant
}))
```

- Create keys with the minimum permission needed (read-only for market/account calls).
- Restrict the key to specific IPs where KuCoin allows it.
- This library never logs `KC-API-KEY`, `KC-API-SIGN`, `KC-API-PASSPHRASE`, or full private request bodies.
- It never places live trading, transfer, or withdrawal calls in its own tests, examples, or CI.

See [SECURITY.md](SECURITY.md) to report a vulnerability.

## UTA versus Classic

KuCoin exposes two distinct account models with different permissions, hosts, and data shapes. This SDK keeps them as **explicit, separate service roots** — `client.UTA` today, `client.Classic` once implemented — rather than merging them into one type, since doing so would misrepresent which fields/permissions actually apply. Do not assume a UTA and a Classic response for "the same" concept (e.g. a kline) share a struct — see the field-order note on `market.Kline`.

If you're not sure which model your account uses: UTA is KuCoin's newer, unified margin/futures/spot account; Classic is the older, separately-funded Spot/Margin/Futures setup. Check your KuCoin account settings if you're unsure — the two are not interchangeable at the API level.

## REST examples

**Market data (public, no credentials):**

```go
book, err := client.UTA.Market.GetOrderBook(ctx, market.TradeTypeSpot, "BTC-USDT", market.GetOrderBookOptions{Limit: 20})
```

**Error and rate-limit inspection:**

```go
_, err := client.UTA.Market.GetTickers(ctx, market.TradeTypeSpot, "BTC-USDT")
if errors.Is(err, transport.ErrRateLimited) {
	// back off
}
var kucoinErr *transport.KucoinError
if errors.As(err, &kucoinErr) {
	fmt.Println(kucoinErr.HTTPStatus, kucoinErr.Code, kucoinErr.Message)
}
```

Authenticated account/order examples aren't shown here because that domain isn't implemented yet — see **Status** above.

## Configuration

| Option | Description | Default |
|---|---|---|
| `WithCredentials(Credentials)` | API key/secret/passphrase/key-version | zero value (public-only) |
| `WithUTABaseURL(string)` / `WithClassicBaseURL(string)` | Override REST hosts | `https://api.kucoin.com` |
| `WithHTTPClient(*http.Client)` | Inject a custom HTTP client | `&http.Client{Timeout: 15s}` |
| `WithTimeout(time.Duration)` | Timeout for the internally built HTTP client | `15s` |
| `WithSiteType(SiteType)` | `X-SITE-TYPE` header (`global`/`australia`) | `global` |
| `WithEnableNS(bool)` | Send `kc-enable-ns: true` for nanosecond response timing | `false` |
| `WithClock(Clock)` | Inject a clock (tests, clock-skew correction) | system clock |
| `WithLogger(Logger)` | Structured logger (never logs credentials) | no-op |
| `WithRetryPolicy(*RetryPolicy)` | Override the default GET-only retry policy | `NewDefaultRetryPolicy()` |

## A few practical tips

1. **Use strings for money.** Every numeric financial field in this SDK is a `string`. Reach for `math/big.Rat` or a decimal library when doing arithmetic; avoid `strconv.ParseFloat` where precision matters.
2. **Check `docs/ENDPOINTS.md` before assuming coverage.** This is an in-progress SDK — don't assume a method exists just because the equivalent REST endpoint is documented by KuCoin.
3. **Pass contexts with deadlines.** Especially relevant once trading endpoints land — a slow request can outlive its usefulness.
4. **Check errors by type.** Use `errors.Is` for sentinel errors like `transport.ErrRateLimited` and `errors.As` for `*transport.KucoinError` instead of matching on error strings.
5. **Watch the retry policy.** Only GET requests are retried automatically. Once order/transfer endpoints ship, treat every write call as "fires once" unless you add your own idempotency handling.
